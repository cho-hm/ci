# LLM WIKI

이 디렉터리는 **LLM이 읽고 쓰는 지식 베이스**다. 여기 문서는 **토큰 효율적이고 구조화된 Markdown**으로 작성되어 AI 에이전트가 과거 작업 맥락·결정·이유를 빠르게 회수하도록 설계됐다.

## 목적

- 완료된 작업(PR 단위)의 **무엇을·왜·어떻게**를 기록한다.
- 다음 에이전트/사람이 "이거 왜 이렇게 했지?"를 코드/깃 히스토리보다 빠르게 파악한다.
- 코드에 드러나지 않는 **결정 근거·트레이드오프·후속 과제**를 남긴다.

## 구조

```
docs/wiki/
├── README.md            # (이 파일) 위키 사용법
├── INDEX.md             # 전 항목 1줄 색인 — 회수 시 항상 먼저 읽는다
├── _TEMPLATE.md         # 새 항목 작성 템플릿
└── entries/
    └── <YYYY-MM-DD>-<slug>.md   # 항목 1개 = 작업(PR) 1건
```

## 사용 규칙 (에이전트용)

1. **회수(읽기)**: 먼저 [`INDEX.md`](INDEX.md)를 읽어 관련 항목을 고르고, 해당 `entries/*.md`만 읽는다. 전체 파일을 무작정 덤프하지 않는다. → `/wiki-search` 스킬.
2. **기록(쓰기)**: 작업 완료(주로 PR 생성) 후 `_TEMPLATE.md` 형식으로 `entries/`에 항목을 추가하고 `INDEX.md`에 1줄 포인터를 넣는다. → `/wiki-record` 스킬.
3. **1항목 = 1작업**: PR/이슈 단위로 쪼갠다. 너무 크면 분할한다.
4. **최신 우선**: 같은 주제의 이전 항목이 있으면 새로 만들지 말고 갱신하거나, 상단에서 최신 항목으로 링크한다.
5. **링크**: 항목끼리 `[[entries/<file>]]` 또는 상대경로로 상호 참조한다.

## 항목 프론트매터

```yaml
---
title: <한 줄 제목>
date: <YYYY-MM-DD>          # 작업 완료(머지/PR) 기준
issue: <UNION-XXX | -->     # 관련 지라 이슈
pr: <PR URL 또는 번호 | -->
branch: <브랜치명>
repo: <리포명>              # 예: ci
status: merged | open | wip
tags: [ ... ]               # 검색 키워드
---
```

본문 섹션은 `_TEMPLATE.md` 참고.
